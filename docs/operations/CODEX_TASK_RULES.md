# Codex 작업 규칙 (2026-09-05)

어젯밤(2026-09-04) 두 번의 사고에서 나온 규칙이다. 모든 Codex 스펙 파일 머리에 이 규칙을 그대로 붙인다.

## 1. 스케줄 실행 창에는 `src/stock_data`를 편집하지 않는다

예약 작업은 저장소의 **작업 트리를 그대로 임포트**한다. 레인 실행 도중 지연 임포트되는 모듈이 편집 중이면 번들이 중간에 죽는다(2026-09-04 20:30 번들: 영수증 없이 종료, 점유 기록이 미완료로 남음).

| 창 (KST) | 실행되는 것 |
|---|---|
| 06:00–06:40 | FRED, 글로벌 ETF/주식(06:10), 글로벌 지수(06:20), 헬스(06:30) |
| 09:05–09:25 | KR 09:10 번들 |
| 14:05–14:25 | KR 14:10 번들 |
| 16:05–16:25 | 텔레그램 마감 브리프(당일 잠정 갱신 포함) |
| 20:25–21:05 | KR 20:30 번들(파생·수급·지수·주간 OpenDART·전방검증) |

- 이 창에는 `src/stock_data`, `scripts/maintenance`, `scripts/manual/collect`를 건드리는 Codex를 띄우지 않는다. 창 직전에 끝나지 않을 작업은 창 이후로 미룬다.
- 웹 전용(`src/stock_web`) 작업은 창과 무관하다.
- 대안(대기 항목): 예약 작업을 고정 워크트리(`git worktree`)에서 실행해 편집과 분리한다.

## 2. 웹 작업은 파생 계산 코드를 건드리지 않는다

2026-09-03 시장 페이지 작업(543a1fb)이 `src/stock_data/derived/option_walls.py`에 열 20개를 추가했고, 다음 날 20:30 파생 레인이 "prior Wall schema differs"로 실패했다.

- 웹 스펙의 HARD SCOPE에 `src/stock_data/derived`, `src/stock_data/orchestration`, `src/stock_data/contracts`를 **명시적으로 제외**한다.
- 파생 데이터 열이 바뀌면, 그 열을 쓰는 레인·아티팩트(예: `artifacts/analysis/*.csv`의 스키마 비교)를 같은 작업에서 확인한다.

## 3. 실행 방식

- `codex exec`는 반드시 저장소 루트에서 띄운다(다른 폴더에서는 "Not inside a trusted directory"로 즉시 종료).
- 병행 작업은 파일 스코프가 겹치지 않게 나눈다. 같은 파일을 두 작업이 만지면 순차로 돌린다.
- 결과 파일(`-o`)이 비어 있으면 로그 꼬리를 확인한다. 스코프 밖 파일이 필요해 멈춘 경우 그 한 줄은 코디네이터가 직접 처리한다.

## 4. 데이터 안전

- `.env` 금지, 키·토큰·계좌 잔액·보유 수량을 로그·문서·아티팩트에 쓰지 않는다.
- `git add`/`stash`/`checkout`/커밋은 Codex가 하지 않는다. 커밋은 코디네이터가 검증 후 한다.
- Windows 예약 작업은 사용자 허용 하에 코디네이터만 만들고, 만들 때마다 사용자에게 알린다.
