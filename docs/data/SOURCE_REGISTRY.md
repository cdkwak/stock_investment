# Multi-Source Registry

This registry is the Data-layer directory of provider lineage and potential
fallbacks. It is a navigation and control document, not collection authority.
Current routing/status remains owned by [Data Status](DATA_STATUS.md), physical
existence by the Dataset Index and retained state, and schema/PIT rules by the
applicable contract. A source shown here never authorizes a network request,
promotion, or substitution.

## Reading rules

- One row is one source family for one economic variable. Rows sharing a
  variable are alternatives only if `fallback_allowed` explicitly says `YES`.
- Compound fields retain all required registry fields without implying a merge:
  `coverage / granularity / market / session`, `unit / multiplier / value`,
  `date / PIT`, `universe / delisted`, `license / equivalence / fallback`, and
  `collector / state / runbook / evidence / current status`.
- `N/A` means the property is not meaningful for the variable, not that it was
  inferred. `UNKNOWN` is a blocker.
- `license_status` is project-use evidence, not legal advice. `NO` fallback
  means no automatic or approved replacement under the current record.

Round 3 short-trading availability evidence: the official KRX
`MDCSTAT304` screen states that from 2025-03-04 same-date trading details are
provided after 20:00 KST. The project contract remains deliberately stricter:
collection eligibility is the next XKRX session. Scheduler activation is still
blocked by the current runner's separate KOSPI/KOSDAQ promotions, not by an
unknown availability clock.

### Controlled vocabularies

Roles: `PRIMARY`, `PRIMARY_CANDIDATE`, `SECONDARY_EQUIVALENT`,
`EMERGENCY_FALLBACK`, `OFFICIAL_REFERENCE`, `CROSS_CHECK`,
`CURRENT_CROSSCHECK`, `PER_SYMBOL_CROSSCHECK`, `SOURCE_OBSERVATION_ONLY`,
`FORBIDDEN_FALLBACK`, `LICENSE_BLOCKED`.

Equivalence: `CONFIRMED_OFFICIAL`, `CONFIRMED_EMPIRICAL_MULTI_DATE`,
`PARTIAL_EQUIVALENCE`, `UNRESOLVED`, `NOT_EQUIVALENT`.

At registry creation, no row qualifies as an `EMERGENCY_FALLBACK`; that is an
intentional fail-closed result, not a missing implementation.

## Registry implications

- `PRIMARY` describes the currently retained source or a required provider
  segment; it is not a claim of substitutability.
- `PRIMARY_CANDIDATE`, `LICENSE_BLOCKED`, and `SOURCE_OBSERVATION_ONLY` rows
  are never fallback sources.
- A `CROSS_CHECK`, `CURRENT_CROSSCHECK`, or `PER_SYMBOL_CROSSCHECK` record may
  validate an accepted observation but cannot fill a missing primary value.
- `OFFICIAL_REFERENCE` may establish labels, units, or methodology without
  supplying a retained replacement time series. KRX [12012] is exactly such a
  reference for LS t1633.
- FinanceDataReader 0.9.202 is not itself a provider. UR-108 resolved its
  candidate routes to KRX/KIND plus community GitHub caches, Naver, Yahoo,
  Wikipedia, Investing.com, and FRED. Only the exact `FRED:VIXCLS` route passed:
  it is a same-upstream parser fallback after a direct-FRED `SCHEMA_ERROR`, with
  two counted GETs, timeout 10 seconds, retry zero, raw-missing rejection,
  provider-specific Landing and atomic circuit/provenance promotion. Every
  other route remains `fallback_allowed=NO` or cross-check-only. This is a
  route-level decision, not a blanket package approval. The former UR-108
  matrix artifact is not retained; this registry and the current Source
  Fallback Policy own the surviving route decisions.

Fallback decisions are governed solely by [Source Fallback Policy](SOURCE_FALLBACK_POLICY.md).
