# 검증 페이지 파라미터 실험

## 빠른 사용법

복리 사다리 빠른 사용법

- 낙폭·이격도는 진입 문턱, 분할 수와 배율은 위기 때 옮길 노출을 정합니다.
- 적합 구간(~2015)은 자유롭게 탐색하고, 홀드아웃(2016~) 열람은 매번 기록됩니다.
- 마음에 드는 조합을 후보로 등록하면 자동 포워드 테스트가 시작됩니다.

## 동작 경계

패널은 `artifacts/research/compound_ladder/grid_<basket>_<product>.json`의
캐시 행만 조회한다. 조절판 변경은 브라우저 메모리에서 처리하며 요청 경로에서
백테스트를 계산하지 않는다. 정확히 일치하는 행이 없으면 `미계산 조합`으로
표시한다. 자산 곡선과 사이클은 산출물이 이름 붙여 보존한 행에만 표시한다.

홀드아웃은 기본적으로 감춰져 있다. 사용자가 현재 조합의 홀드아웃을 열 때마다
후보 레지스트리의 시도 횟수와 이력에 조합 및 UTC 열람 시각이 원자적으로
기록된다. 후보 등록은 기존 후보 등록 경로를 사용한다. UI 요청 정의에는 선택한
분할 수를 유지하되, 기존 포워드 레인의 “조건 수 = levels” 계약에는 두 진입
조건으로 변환한다. 선택한 분할 수는 등록 이유에 남고 출구·배율·비용은
`compound_ladder_ui` 메타데이터로 함께 보존된다. 결과 상태 줄은 지수, 선택한
상품 기준(지수 1x/합성 2x/합성 3x/실제 상품 보정), 거래비용 포함 여부, cached
row 여부를 함께 밝힌다. 후보 메타데이터와 화면의 재현 CLI도 같은 비용 플래그를
보존한다.

`계산 실행`은 loopback 및 private mode에서만 사용할 수 있다. 한 번에 한 작업만
`artifacts/research/compound_ladder/run.lock`을 소유하며, 진행 상태는 `run.log`에
추가된다. 작업은 retained 데이터만 읽는 기존 compound-ladder 엔진을 호출하고
grid와 summary를 원자적으로 갱신한다. 공급자 API와 주문 경로는 호출하지 않는다.
표준 범위는 스크립트 명령을 그대로 보여 주며, 범위를 덮어쓰면 동일 공개
`run()` 함수와 선택 범위를 호출하는 재현 가능한 Python 명령을 보여 준다.

공개/게스트 모드에서는 패널을 렌더링하지 않으며 `/api/research/compound/*`
전체가 존재하지 않는 것처럼 HTTP 404를 반환한다.

## 위기 정렬 겹쳐보기

`위기 정렬 겹쳐보기`는 핵심 실탄 표의 사전 정의 사이클에 속한 독립 2단계
에피소드를 `x=0`으로 맞춘 −60~+250 시장 세션으로 표시한다. schema v2
`overlay.json`은 `보유시작 = 100`과 `신호일 = 100` 경로를 모두 선계산하며,
기본값은 실탄 관점인 보유시작 기준이다. 보유시작은 핵심 실탄 표와 똑같이
T−60 또는 그 이후 마지막 level-0일이다. 따라서 KR 2022-09-30 TLT의 T 값
88.11처럼 T/+20/+60 체크포인트가 `core_ammunition` 표의 as-of 및
duration/cash 계산과 일치한다. `WORST@T`는 표시 기준과 무관하게 이 보유시작
valuation으로 판정한다. 차트 제목, 왼쪽 y축, 아래 캡션은 현재 기준과 일치하는
표를 항상 명시한다. `주식 vs 10년 금리`는 정규화 자산값을 왼쪽 축, 원시
`dgs10` 금리 수준(%p)을 오른쪽 축에 놓는다.
`낙폭 사다리` 프리셋은 같은 KOSPI 사이클의 100 기준 가격과 관측 LEVEL
(0/1/2) 계단 경로를 함께 표시한다.

요청 경로는 `artifacts/research/crisis_overlay/overlay.json`만 읽으며 계산하지
않는다. 산출물이 없으면 `미계산`과 아래 명령을 표시한다.

```powershell
.venv\Scripts\python.exe scripts/research/run_crisis_overlay.py --project-root .
```

생성기는 retained Parquet만 읽고 결과를 원자적으로 교체한다. 2016-01-01 이후
신호와 사다리 사이클은 기본적으로 숨긴다. `홀드아웃 위기 보기`는 기존
`POST /api/research/compound/holdout-view`에 `kind=crisis_overlay`를 보내 동일한
시도 이력과 세션 카운터를 증가시킨 뒤 공개한다. 공개/게스트 모드에서는 패널과
`GET /api/research/crisis-overlay`가 모두 HTTP 404로 숨겨진다.
두 패널 중 어느 쪽에서 홀드아웃을 열어도 응답의 영구/세션 카운터를 두 패널에
동시에 반영한다.

## 고원 지도 규칙 (2026-09-05 확정)

- 고원 지도의 표면은 **화면 손잡이를 따라간다**: 축 두 개만 변하고 나머지(다른 임계값·분할·배율·출구·거래비용·기본 노출)는 지금 화면의 값이다. 캐시에 그 표면이 없으면 판정 문구를 숨기고 "이 조합의 고원 판정은 아직 계산 안 됨"을 보인다. 다른 조합의 판정을 대신 보여주지 않는다.
- **비용률·세율은 그리드 축이 아니라 시나리오 고정값**이다. 그리드 파일에는 거래비용 켬/끔 두 시나리오가 모두 열거되어 있지만(행 수 검산에 ×2로 들어감) 이는 '두 시나리오를 각각 보존'한 것이고, ★ 최적 탐색·고원 판정·후보 등록은 항상 화면에 고른 한 시나리오 안에서만 움직인다. 비용률을 바꿔 가며 최적을 찾는 경로는 없어야 한다. "얼마가 제일 좋은가"를 찾는 파라미터가 아니라 "실제로 얼마인가"를 넣는 상수다. ★ 최적 탐색은 한 비용 시나리오 안에서만 돈다. 데드밴드(실행 방식)는 탐색 가능하다.
- best 를 고르는 모든 경로는 `select_best_in_scenario` 를 통해 시나리오를 명시적으로 받는다.
- `heatMetric()`은 **fit 창만** 읽는다. 고원 지도에 홀드아웃이 새지 않는다.
- **고원 판정은 3단계**다: 표면 분산 ≈ 0 → "이 조합에서는 파라미터가 결과를 바꾸지 않음"(k=1, 전멸 등 퇴화 조합, 판정 대상 아님) / 최적 ≤ 기준선 → "전 구간 기준선 미달"(평탄도 판정 없음) / 최적 > 기준선일 때만 "넓은 고원"·"뾰족한 봉우리". 원칙: **가장 긍정적으로 읽히는 문구는 가장 엄격한 조건에서만 나온다.** 새 판정·요약 문구를 만들 때마다 "이 문구가 나오면 안 되는 조합에서 나오지 않는가"를 검사한다.
- 최종배수 0.00배는 계산 실패가 아니라 실제 전멸 경로(3배 · 출구 d)이며 "전액 손실"로 표기한다. 표에서 지우지 않는다.
- **라벨 규칙(2026-09-05, 볼트 세션)**: 새 표시·판정 문구를 만들 때마다 "이 라벨이 사실이 아닌 경우가 있는가"를 묻는다. 오늘 세 번 걸렸다 — 고원 지도가 손잡이와 다른 조합을 설명(05:20), '넓은 고원'이 무효과·전멸 설정에 붙음(05:25), '실제 상품 보정'이 보정 드래그 0인데 보정이라는 이름을 달고 있음(22:00 → 이제 '보정 없음(양수 갭 · 합성 그대로)'). 화면이 멀쩡히 돌고 숫자가 그럴듯할수록 더 의심한다.
- **기본값 규칙(2026-09-05, 볼트 세션)**: 보수적 기본값(예: 보정 드래그 `max(0, −gap)` → 0)으로 떨어졌을 때 **왜 떨어졌는지가 화면에 보여야 한다**. 매핑이 틀려서 0인지 정말 보정할 게 없어서 0인지 구분되지 않으면 오류가 정상처럼 보인다 — '보정 없음(양수 갭 · 합성 그대로)' 표기가 그 예. 같은 이유로 `leveraged_product.validate_real_product_map()`이 한 상품이 여러 기초지수에 배정되면 import 시 경고한다.
