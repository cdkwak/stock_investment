# 연구 계산 계층 구조 재구축 결과 (2026-09-06)

이 문서는 이번 엔진 재구축의 결과 파일이다. 새 백테스트 숫자나 새 기본값을 만들지 않았고, 전체 그리드·retained 결과 산출물·기존 `RESULTS_*` 문서는 실행하거나 갱신하지 않았다.

## 구조 변경

- `LadderSpec`의 `drawdown_threshold`, `disp60_threshold`, `product_share_at_max`는 값이 없으면 규칙 ⑥ 오류를 낸다. `levels`와 `base_exposure`의 기존 의미는 유지한다.
- 최고 단계의 상품 비중은 `product_share_at_max`다. 단계 진행률은 `level / levels`이고, 기본 노출이 1 이하일 때 상품 비중은 `진행률 × product_share_at_max`다. 기본 노출이 1보다 크면 기존 기본 상품 비중에서 명시한 최고 상품 비중까지 보간하며, 최고 비중이 기본 노출이 요구하는 상품 비중보다 작으면 오류를 낸다.
- 계좌 곡선은 `effective_exposure = core_weight + leverage_multiple × product_weight`를 명시한다. `SimulationResult`, 새 grid 행, leaderboard 후보 행은 최고 단계의 `effective_exposure_max`를 노출한다. baseline 행은 `product_share_at_max=null`, `effective_exposure_max=1.0`; 배분 결정이 없는 leaderboard 행은 두 필드를 `null`로 두어 결정값처럼 보이지 않게 한다.
- `ladder_levels`는 `BuySignalSpec`을 받을 수 있다. 생략 경로는 현재 B 규칙을 옮기는 동안만 쓰는 얇은 호환 경로이며, 이때도 두 임계값은 `LadderSpec`에 명시해야 한다.
- `compute_signal_features`는 기존 close-T 계산기에서 `drawdown252`, `disp60`, Wilder `rsi14`를 재사용한다. D는 지정 N일 낙폭 변화, E는 마지막 낙폭 구간 진입 뒤의 누적 저점을 인과적으로 계산한다. 미래 결과 열은 feature/signal 입력에 사용하지 않는다.
- 기존 홀드아웃 시작일, 열람 횟수, 후보/채택 상태, 3단계 고원 문구, `index_basis`, 포워드 기록 형식은 바꾸지 않았다. 기존 schema의 compound grid는 읽을 수 있지만 상품 비중이 없는 과거 행은 새 leaderboard 교차참조에서 `unavailable`로 남아 새 결정값처럼 표시되지 않는다.

## 호출 예

값은 호출자가 명시한다. 아래 숫자는 새 기본값이 아니라 인자 모양을 보이는 예시다.

```python
spec = LadderSpec(
    drawdown_threshold=chosen_drawdown,
    disp60_threshold=chosen_disparity,
    product_share_at_max=chosen_product_share,
    levels=chosen_levels,
    base_exposure=chosen_base_exposure,
)
```

CLI 실행기에는 `--drawdown-threshold <결정값>`, `--disp60-threshold <결정값>`, `--product-share-at-max <결정값>`을 모두 넘겨야 한다. 하나라도 없으면 retained 데이터 로드나 결과 쓰기 전에 `<이름> is undecided under rule ⑥; caller must pass it explicitly` 오류를 낸다.

## 매수 후보 A–E

| kind | 정의 | 필수 파라미터 |
|---|---|---|
| A | `drawdown252 <= drawdown_threshold` | `drawdown_threshold` |
| B | A이고 `disp60 <= disp60_threshold` | `drawdown_threshold`, `disp60_threshold` |
| C | A이고 `rsi14 <= rsi14_threshold` | `drawdown_threshold`, `rsi14_threshold` |
| D | A이고 `drawdown252.diff(N) >= -tolerance`; 낙폭 확대가 멈추거나 허용 오차 안으로 둔화 | `drawdown_threshold`, `deceleration_lookback_days`, `deceleration_tolerance` |
| E | 마지막 `drawdown252 <= drawdown_threshold` 구간 진입 뒤 누적 저점 대비 `rebound_pct` 이상 반등 | `drawdown_threshold`, `rebound_pct` |

각 kind에 필요한 파라미터가 빠지면 그 파라미터 이름과 규칙 ⑥을 포함한 `ValueError`를 낸다. A–E는 후보 정의일 뿐 채택된 투자 규칙이 아니다.

## 매수/매도 점수 계약

- `score_buy_events`: 21·63·126·252 retained session의 전방 수익률 평균, 중앙값, 양수 비율을 계산한다.
- `score_sell_events`: 호출자가 넘긴 각 horizon의 전방 연환산 실현변동성과 경로 최대낙폭을 각각 평균·중앙값으로 계산한다. 전방 수익률이나 승률로 매도 신호를 판정하지 않는다.
- 두 함수 모두 `events_total`과 기존 leaderboard의 90일 사건 묶음 helper를 재사용한 `events_independent`를 낸다. 독립성 규칙을 복제하지 않았다.
- leaderboard의 매수 headline은 `return_win_rate`, 과열/매도 headline은 `realized_volatility_max_drawdown`으로 분리했다. 과열 후보의 `disp60` 상단, `rsi14` 상단, `volidx_pct` 하단 조합을 모두 점수에 포함한다.
- `result_card`는 한국어 한 줄 정의, 총/독립 사건 수, 1·3·6·12개월 평균·중앙값·승률 표, 신호일 100 기준 ±252-session 평균 경로를 낸다. 카드 validator는 사건 수나 중앙값 필드가 빠진 카드를 거부한다.

## PIT·분할 점검

- feature는 각 행의 T 종가와 그 이전 값만 사용한다. D의 `diff(N)`은 과거 행만, E의 저점 상태는 앞에서 뒤로만 갱신한다.
- `ladder_levels`의 관측 단계는 기존처럼 한 retained session 뒤에 `executable_level`이 된다.
- 전방 return/volatility/MDD는 `scoring.py`에 격리되어 신호 feature namespace로 역류하지 않는다.
- 최종 holdout 경계와 열람 카운터는 변경하지 않았고 이번 작업에서 holdout 또는 전체 grid를 실행하지 않았다.
