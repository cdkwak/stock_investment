# Define a PIT-vintage-aware macro regime and market-transmission contract

## Problem
No PIT-vintage-aware semantic boundary combines exact growth, inflation, employment, liquidity, credit, fiscal, FX and commodity evidence into conflict-aware macro states or bounded non-causal asset/sector/account transmission explanations.

## Evidence
PROJECT_GOAL requires leading/coincident/lagging evidence, trend/surprise/revisions, explicit regime conflicts and uncertainty, exact release/vintage metadata, next release and then-public historical replay. Current FRED use is descriptive/PIT-blocked and Backtest blocks FX/wider families; BB30 and other queued contracts are narrower consumers.

## Scope

- After BB30 acceptance, create the future Project-owned documentation contract and update Project Status routing only.

deny:
- No provider choice/call, Data write/promotion, inferred vintage/expectation, regime/model/strategy implementation, GUI change, account access, optimization, recommendation/order, or wider phase selection.
